# 选题验证

回答一个问题：这个选题在抖音上被验证过吗？方法是找同一选题的其他爆款，逐条核数，再看评论区的机制是否一致。

「孤立爆款的改编成功率更低」只是假设，没有被证明。报告里只能写成风险提示，不能当作否定选题的结论。

## 一、判据

下面的数字是默认值，可在配置文件里改。

| 概念 | 判据 |
|---|---|
| 同选题 | 同一个核心矛盾或现实原型，不是同一个关键词。由分析员判定，不交给采集脚本 |
| 有效同题爆款 | 同选题，**且单条评论数 >500**，**且发布日属于当年或上一年**。评论数等于 500、低于 500 或没核实的，不计数 |
| 评论区无效 | 评论以运营、同行互助、抽奖为主的片子，不计数。要抽样看评论构成，不凭评论数判断 |
| 旁证 | 发布日更早的片子，最多额外列 1 条（选评论数最高且 >500 的），标「旁证，不计有效」 |
| 孤立 | 去掉对标本身，有效同题爆款 0 条，**且搜索已完成** |
| 证据薄弱 | 有效同题爆款 1 条 |
| 更高一级 | 有效同题片的评论数 ≥ 对标评论数 × 2，且评论区不是互助或抽奖区 |

- 账号总评论、点赞数、搜索页热度，都不能代替单条视频的评论数。
- 播放量、点赞数不设下限，不设时间窗口，只按年份筛。

## 二、步骤

前提：定搜索词之前，已有对标的逐字稿。没有逐字稿就先转录对标视频：首选你自己已有的文件；没有时可选用「保存当前视频用于学习研究」（只保存对标这一条）。不凭标题、封面、评论区猜内容。

1. **读推荐视频。** 打开对标视频页，读页面上的「推荐视频」，约 10 条；同时读对标的读数和抽样评论。这一步不搜索，可以和转录同时做。
2. **写选题卡。** 等逐字稿出来，写三行：
   - 一句话选题：谁，在什么场景，遇到什么矛盾。
   - 现实原型：生活里对应哪类真实情况。
   - 依据：逐字稿的段号和秒数。
   - 有效台词少于 3 句（纯画面、纯音乐、只有字幕）时，先截关键帧，看画面和屏幕字幕再写。仍说不清就停下，问用户这条讲什么，不猜。
3. **定搜索词。** 列 3–6 个，分三组，每组至少 1 个：
   - 场景与原型词，例如「长期出差 总部」。
   - 矛盾词，例如「回公司 不认识」。
   - 观众说法：从对标高赞评论里取观众对这件事的叫法。只用来扩词，不用来判内容。
4. **搜索（必做）。** 不论推荐里有几条有效同题，都搜完全部搜索词。从首页搜索框搜，只取「视频」标签首屏。
5. **逐条读视频页。** 每个候选只打开一次，一次读完：赞、评、藏、转、发布日、简介、作者主页链接。评论数 >500 且年份合格的，当场抽样抓评论。
6. **判同题。** 按第一节判同题、判有效。
7. **评论分簇。** 对标单独分簇一次；所有有效同题片的评论合成一个池子，分簇一次。方法见 [评论机制](评论机制.md) 第四节。
8. **对标复原。** 把对标评论的大簇对到镜次，填评论触发表。方法见 [对标复原](对标复原.md)。
9. **判情形、出报告。** 用 [报告模板](../templates/选题验证报告.md)。报告写明选题卡、每个搜索词属于哪一组。

访问节奏、抽样口径、失败处理见 [采集规则](采集规则.md)。

### 搜索出现空结果

空结果不等于没有同题片，也不一定是被限流。

1. 停下这一轮，不重试，不换路径硬刷。
2. 记「待补搜」：搜索词、时间、页面文字前 300 字。
3. 打开一个视频页，确认登录状态正常。
4. 搜索没做完，**不出「孤立」结论**，情形记 D。

## 三、四种情形

| 情形 | 条件 | 报告怎么写 |
|---|---|---|
| A 正常 | 有效同题 ≥2 条，没有更高一级 | 选题已被验证。同题评论簇并入结论 |
| B 有更高一级 | 有效同题片评论数 ≥ 对标 × 2 | 列出这些片子的链接、读数、倍数。建议你先看它们，再决定参考哪一条。不自动改换分析对象 |
| C 孤立或证据薄弱 | 有效同题 0 条或 1 条，搜索已完成 | 给「做／不做」二选一建议，见第四节 |
| D 搜索未完成 | 空结果、被限流、页面读取失败 | 写「证据不足，待补搜」。不出 C 的结论 |

## 四、做不做：判法

情形 C 必须二选一，不写「无法判断」。依据只用三类：

1. 对标的爆点来自内容机制，还是来自账号本身或热点？
2. 选题的现实原型强不强？现实里这件事常见吗？
3. 有没有旁证（年份更早的同题片、其他平台的同题内容）？

- 三类都弱，才建议不做。
- 三类互相矛盾或证据不足时，仍要选一边，并写明按哪条依据选。
- 写一句「最大的未知项」。
- 建议「不做」时，写明换题方向或放弃理由。建议「做」时，写明主要风险。
- 情形 A、B 也写一句建议，依据是同题片的机制是否一致（[评论机制](评论机制.md) 第五节）。

## 五、不做什么

- 不把「孤立」写成「必败」。
- 不凭评论数代替逐条评论构成的判断。
- 不滚动翻页搜索结果，不并行打开多个抖音页面，不缩短访问间隔来赶进度。省时间靠少访问（合并读取、预筛、缓存），不靠缩短间隔。
- 等待访问间隔时，可以同时跑不访问抖音的本地任务（转录、分簇）。
